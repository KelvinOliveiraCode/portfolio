Single-page personal portfolio, bilingual Portuguese/English, no framework and no build step. Gathers 97 public repositories, nine with a published page, four bootcamp certificates, and contact information.

## Problem / Why it exists

The site exists to gather, in a single place that can be opened and shown, the published work — projects with a live page, the archive of the 97 public repositories, bootcamp certificates with verification links, and contact channels. All without depending on an intermediary platform — the repository is the source and the deploy goes straight from it.

## What it does

- Presents the profile in six sections — About, Skills, Projects, Certificates, Areas, Contact.
- Shows a showcase of nine projects with a published page, with description, stack, and links to the site and the code.
- Lists the full archive of the 97 public repositories with filter by six areas, name search (without depending on accents), batch loading, and empty state when nothing matches.
- Displays four DIO certificates (Bradesco, Riachuelo, Santander and CI&T) with direct verification links.
- Switches between Portuguese and English in 567 page elements, with the choice saved in localStorage.
- Animates counters (100+ repositories, 12 live pages, 4 bootcamps, 169 hours of training) and reveals elements on scroll, with scroll fallback when the browser does not support IntersectionObserver.

## Stack

- HTML5, CSS3 and JavaScript with no external dependencies
- Cormorant Garamond font (Google Fonts)
- SVG icons embedded in HTML
- JSON-LD (Person) metadata, Open Graph and sitemap.xml
- Project data is generated with two PowerShell scripts (`_gen.ps1`, `_cards.ps1`) from four JSON files in `_fonte/`
- Published with GitHub Actions and GitHub Pages on every push to the `main` branch (`.github/workflows/deploy.yml`)

## How it works

The page is a single `index.html` file with anchors by section. No build or server; opens directly in the browser.

- The 21 showcase highlights appear six at a time; the "Show more" button reveals the rest and disappears when the list ends.
- The archive shows the 97 repositories from `assets/projetos.js`, generated from a GitHub API snapshot. Filters by area (Data & AI, Backend, Web & Product, Cybersecurity, Networks & Infrastructure, IT & Support) and name search with accent-free normalization. Filter and search always return to the first batch.
- The language is switched by `i18n.js`, which reads the `data-pt` / `data-en` attributes; default is Portuguese, English when the browser is not PT, and the choice persists in `localStorage`.
- Reveal uses IntersectionObserver with a scroll safety sweep, so no section stays invisible. The background video loads with `requestIdleCallback` and is removed on data-saver or reduced motion; the CSS poster stays in place of the video. Progress bar, active section in navigation, and back-to-top button use scroll with time throttle. On mobile, touch targets are 44px or larger.
- The counter numbers are already written in HTML; the animation is decoration, not the data source.
- The "live" badges were checked one by one for HTTP 200. Five repositories returned 404 on verification (`olaria`, `slidestage`, `finvibe-ai`, `opencode-browser-chat`, `livro-financeiro`) and got no badge.

## How to run

Open `index.html` in the browser. No dependencies, build or server.

To regenerate project data (for example, update the GitHub API snapshot), run the `_fonte/` scripts with PowerShell, at the repository root or inside `_fonte/`.

```powershell
# 1. generates assets/projetos.js from _raw.json and _curadoria.json
powershell -File _fonte/_gen.ps1

# 2. injects showcase and archive cards into index.html
powershell -File _fonte/_cards.ps1
```

`_cards.ps1` is idempotent — restores the `<!--#VITRINE#-->` and `<!--#ARQUIVO#-->` markers before reinjecting, so it can run as many times as needed without dirtying the HTML.

`_raw.json` is a static API snapshot (`https://api.github.com/users/KelvinOliveiraCode/repos?per_page=100`), not a live source. To update for real, download the file again, replace `_raw.json` and run `_gen.ps1`.

## Trade-offs and decisions

- Without framework and build, the site deploys directly from the repository via GitHub Actions. This avoids dependencies but makes editing the file by hand less practical, since the project index is generated by script.
- Background video only loads when worth it (`requestIdleCallback`, disabled on data-saver and reduced motion); the CSS poster replaces the video when it does not load.
- Counter animation is decoration — the final number is already in HTML, so nothing disappears if the browser does not animate.
- Archive filter and search always return to the first batch; the "Show more" button disappears when there are no more items.
- The language stays in `localStorage`; the default is Portuguese.
- Project data is an API snapshot, downloaded manually; updating requires re-downloading the JSON and running the scripts in `_fonte/`.

## Known limitations

- Projects are not live — they reflect the snapshot in `_raw.json`. Repositories created after the session do not appear without regenerating `assets/projetos.js`.
- Five repositories returned HTTP 404 on live page verification (`olaria`, `slidestage`, `finvibe-ai`, `opencode-browser-chat`, `livro-financeiro`) and got no "live" badge.
- The site is single page — there are no per-project pages; each item points to GitHub or to the published page when it exists.
- No automated tests for the site (HTML/CSS/JavaScript).
- The desktop version of the study app (Java 21 + JavaFX + SQLite) is Windows-oriented (zip with embedded JRE 21 via `jpackage`); the development command assumes a local Maven installation.
